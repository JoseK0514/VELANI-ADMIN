## Retention and recovery

Prospects90days from original creation; edits/closure/reopen never reset it. Engaged business closure12calendar months; reopening before expiry requires new confirmed work. Case content unavailable at original source expiry (hub usually88days), internal transient case/notes purged by source+90days. Client/project/contact/note deletions cascade; cases unlink without extending source expiry. Holds apply only to reviewed internal business records, with a private reason/owner/review date; they never preserve a source request message. Expired review dates do not extend a hold. Audit and minimal command receipts365days; authentication/rate remnants expire separately.

Private holds, classifications, source reassignment or contact erasure require a reviewed operator SQL transaction; no public DELETE/merge/hold/reassignment route is provided. Holds must not promote an expired prospect or reset its original deadline. An expired object retained for review cannot be resurrected through a business command.

Deletion journal stores only entity type/UUID/time/sequence in the separate store. It is append-only to maintenance, read-only to web, and must outlive every restorable admin backup. No ordinary v1 procedure truncates it. Journal metadata lifecycle needs a separate reviewed archival decision; it is not a retained contact/message copy. Never restore both stores together or restore a backup older than the approved retention/restore coverage.

Web transactions take a shared journal lock and require journal maximum sequence=local applied watermark. Maintenance takes the exclusive lock, durably commits deletion intent first, deletes admin rows, then advances the watermark. Crash or restored older data fails closed until private reconciliation. Local tests verify crashes between intent and deletion, source expiry, reviewed holds, dependent-note cleanup and restoration with preserved external journal. Snapshot restore into a real hosted branch still needs explicit restore/delete approval and separate evidence.

Recovery of lost passkeys is `npm run operator -- recover-owner --environment ... --apply` after Jose's private provider-owner verification, using the existing pinned identity. It increments generation, revokes sessions/keys, consumes pending challenges and opens a15-minute enrollment window. It does not rebind Google or trust an email message. No customer credential or employee sign-in behavior changes.
